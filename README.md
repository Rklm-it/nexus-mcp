# Nexus MCP — хаб диагностики нод

MCP-сервер, через который Claude сам проверяет ноды: почему нода красная в
панели, жива ли она, режут ли её IP у домашних провайдеров и какой протокол
на ней работает на самом деле. Подключается к claude.ai как коннектор, так же
как Video.

**Развернуть на VPS по шагам — [DEPLOY.md](./DEPLOY.md).**

## Зачем отдельный хаб, а не ручка в brain

Brain стоит на российском IP, и **путь от него к нодам режется**: TCP
открывается, а пакеты с данными пропадают (разбор 22.09.2026,
`docs/journal/MONITORING.md`). Красные ноды через brain недоступны вообще.
Поэтому хаб ставится туда, откуда до нод достаётся, и ходит к ним по SSH.

Для домашних нод дата-центр видит РФ не так, как Ростелеком или Дом.ру.
Поэтому есть **домашние пробники**: маленький скрипт на домашнем компьютере или
роутере. Он сам подключается к хабу и выполняет проверки из домашней сети.

```
 claude.ai ──https──▶ хаб (MCP) ──ssh──▶ ноды
                        ▲   └──https──▶ brain (список нод, heartbeat, check-host)
     домашний пробник ──┘ (long-poll: проверки из домашней сети)
```

## Куда ставить

Туда, откуда до красных нод проходят **данные**, а не только TCP. Проверка с
кандидата (подставьте IP красной ноды):

```bash
IP=203.0.113.7
timeout 10 bash -c "exec 3<>/dev/tcp/$IP/22; head -c 40 <&3"; echo          # SSH-баннер: данные ОТ ноды
timeout 10 openssl s_client -connect $IP:443 </dev/null 2>&1 | grep -E "Protocol|Cipher|errno" | head -3   # данные в обе стороны
```

Баннер `SSH-2.0-…` и строка `Protocol` в ответе — подходит. Висит — у этой
машины та же беда, что у brain. Тогда нужен другой хостер: зарубежная VPS или
любая живая нода.

## Установка

Репозиторий приватный: на хабе нужен токен GitHub на чтение этого репо
(fine-grained PAT → Repository access: `nexus-mcp` → Contents: Read-only).

```bash
git clone https://<PAT>@github.com/Rklm-it/nexus-mcp.git /root/nexus-mcp && cd /root/nexus-mcp
bash install.sh --domain mcp.example.ru \
  --brain-url https://panel.example.ru --brain-token <X-Admin-Token панели>
```

Или одним скриптом: `bash install.sh --token <PAT> --domain …` — клонирует сам и не
оставляет токен в `.git/config`.

- `--domain` — A-запись на IP хаба. Коннектор claude.ai ходит только по https,
  сертификат выпускает Caddy. Нужен свободный 80 порт.
- Если 443 занят (например, xray на ноде), добавьте `--port 9443`.
- `--no-caddy` — если TLS отдаёт ваш собственный прокси на `127.0.0.1:8765`.

Код встаёт в `/opt/nexus-mcp/app`. Рядом кладётся разреженный клон панели
`/opt/nexus-mcp/vgx3d` (5 МБ): из него хаб берёт `xray_json.py`, тот же
сборщик клиентских конфигов, что у подписки.

В конце установщик печатает:
1. **адрес коннектора**: `https://<домен>/mcp/<секрет>`;
2. **публичный ключ хаба**: его нужно добавить на каждую ноду в
   `/root/.ssh/authorized_keys`;
3. **команду для домашнего пробника**.

Остальные настройки живут в `/etc/nexus-mcp.env`, после правки —
`systemctl restart nexus-mcp`:

| Переменная | Что |
|---|---|
| `NEXUS_TEST_SUB_URL` | подписка тестового юзера, привязанного ко всем нодам: из неё берутся ссылки для сквозной проверки |
| `NEXUS_ALLOW_ACTIONS=1` | разрешить действия (обновить агент, перезапуск, адрес панели); каждое ещё требует `confirm=true` |
| `NEXUS_BRAIN_BASIC_AUTH` | `user:pass`, если `/api` панели закрыт basic_auth |

Ноды берутся из панели. Поправки и ноды вне панели — в `/etc/nexus-mcp/nodes.json`:

```json
{"defaults": {"ssh_user": "root", "ssh_port": 22},
 "nodes": [{"name": "de-1", "ssh_port": 2222}, {"name": "old-nl", "ip": "198.51.100.4"}]}
```

## Ключ хаба на ноде, до которой не достать из РФ

Если по SSH на ноду не зайти ни из дома, ни с хаба (он ещё без ключа), ключ
можно добавить так:
- через веб-консоль (VNC) хостера;
- с хаба по паролю: `ssh-copy-id -i /etc/nexus-mcp/id_ed25519.pub root@<IP>`;
- через живую ноду как прыжок: `ssh -J root@<живая> root@<красная>`.

## Домашний пробник

`probe.py` — один файл на стандартной библиотеке Python 3.8+: Windows, Linux,
роутер с python3. Для сквозной проверки нужен ещё бинарник xray.

```bash
python3 probe.py --hub https://mcp.example.ru --token <PROBE_TOKEN> --name ростелеком-дом --xray ./xray
```

В `--name` лучше писать провайдера: в отчёте будет видно, у кого что режут.
Проверить пробник без хаба: `python3 probe.py --once <IP ноды>`.

Автозапуск на Linux: юнит systemd с `Restart=always`. На Windows: Планировщик
заданий → «при входе в систему».

## Инструменты MCP

| Инструмент | Что делает |
|---|---|
| `nodes_list` | статус в панели, возраст heartbeat, версия агента, доступность из РФ |
| `node_diagnose` | полный диагноз: панель → SSH-обзор → доступность IP с точек обзора → сквозная проверка; находки с `fix` и `next_steps` |
| `fleet_check` | коротко по всем проблемным нодам |
| `node_run` | готовые рецепты: overview, logs, listening, firewall, xray_test, env (без секретов), capture (видит ли нода пакеты клиента), brain_path |
| `node_logs` | журнал vpn-cell / xray / hysteria-server |
| `probes_list`, `probe_check` | точки обзора и одиночная проба (tcp / banner / tls / http) |
| `panel_reachability`, `check_from_russia` | вердикт самой панели и проверка с check-host |
| `fix_playbook` | что делать при симптоме: наш журнал и опыт владельцев VPN-сервисов, со ссылками и степенью доверия |
| `node_action` | restart / set_brain_url / update_agent; только при `NEXUS_ALLOW_ACTIONS=1` и `confirm=true` |
| `audit_tail` | журнал вызовов |

## Безопасность

На хабе лежит ключ ко всем нодам парка, это самая ценная машина. Поэтому:
- **нет произвольного шелла**: только рецепты из `recipes.py` с проверенными
  параметрами;
- **секреты не уходят в вывод**: `.env` печатается с `***`, токен агента
  используется на самой ноде;
- **без секрета длиной от 24 символов** хаб не запускается, любой чужой путь
  получает 404;
- **токен пробника** открывает только `/probe/*`, но не MCP;
- **каждый вызов** пишется в `/var/lib/nexus-mcp/audit.jsonl`.

## Разработка

```bash
git clone https://github.com/Rklm-it/vgx3d.git ../vgx3d   # сторожа сверяют хаб с панелью и нодой
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt pytest
.venv/bin/python -m pytest -q tests
```

Сборщик клиентских конфигов не копируется: хаб грузит
`brain/app/services/xray_json.py` из клона vgx3d по пути (`NEXUS_REPO_DIR`).
Сторожа (отметка конца `cell-update.sh`, пути установщика ноды, порог
heartbeat) сверяются с тем же клоном и без него **падают**, а не пропускаются.

Панель — [Rklm-it/vgx3d](https://github.com/Rklm-it/vgx3d); разборы, откуда
взялось каждое правило, — в её `docs/journal/`.
